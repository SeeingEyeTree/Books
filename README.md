# Angline Ruler

A comedy about a self-declared perfect genius engineer who murders her boss, recruits a coworker, and drives an armored vehicle through a portal into another world to build an empire — told completely straight by its narrator.

## Layout

```
Angline_Ruler/
  knowledge/
    style_guide.md              Voice, POV, humor rules, running jokes, author preferences
    characters.md               Every character, current as of the latest chapter
    world_building.md           Geography, Houses, Pinnacle, history, war, the coast, Earth locations
    magic_system.md             Motes, efficiencies, force physics, runes, cores, doors
    technology_and_industry.md  Billy, weapons, fusion, steel, farms, rail, drones
    current_state.md            Assets, deals, the ledger, open threats — snapshot as of latest chapter
    chapter_plan.md             Summaries of every chapter, status, and plans for what's next
    continuity.md               Open questions and things flagged for revision
  chapters/
    ch01_ladies_and_deadman.md  through
    ch15_unassailable.md
```

## Status

Chapters 1-2 are original rough drafts (past tense, some third-person drift) that still need converting to the house style (first person present). Chapters 3-15 are polished to the current style. See `knowledge/continuity.md` for the specific list of things flagged for revision, and `knowledge/chapter_plan.md` for a chapter-by-chapter summary and what's planned next.

## Working with this repo (for an AI assistant continuing the project)

Read `knowledge/style_guide.md` and `knowledge/continuity.md` first. Then skim `knowledge/current_state.md` for where the plot currently stands. The other knowledge files are reference material — pull in world_building/magic_system/technology_and_industry/characters as needed for whatever scene you're writing. Chapter files are the actual prose; knowledge files are never meant to be quoted back to the reader.

When a chapter is revised, update the relevant knowledge files in the same pass — this repo only stays useful if the knowledge files and the chapters agree with each other.
